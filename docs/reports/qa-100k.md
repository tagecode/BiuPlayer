# 10 万曲目验收（后端）

本机：Intel Core i7-9750H / 16 GB / macOS。

## 搜索

命令：

```bash
cargo run -p biu-library --example bench_100k --release
```

结果：

- 直接插入 100,000 行（含艺术家/专辑/流派/年代）：7,607 ms。
- 数据库大小：30.4 MB。
- 100 次查询：p50 8.83 ms，p95 9.95 ms，max 12.09 ms。
- 目标 ≤100 ms，通过。

说明：查询为 `track 0xxxxx` 形式，命中 FTS5 + BM25；拼音文本已写入 `search_text`，但基准不测拼音展开耗时。

## 扫描

命令：

```bash
cargo run -p biu-library --example scan_bench --release -- 100000
```

结果：

- 生成 100,000 个空 `.mp3`：6,746 ms。
- 首次扫描：100,000 入库，70,617 ms（约 70.6 s）。
- 冷 FTS 查询：75 ms。
- 二次扫描：100,000 跳过，3,023 ms。
- 数据库约 30 MB。

说明：空文件没有标签读取成本，真实曲库会更慢；1 万文件目标 ≤60 s 已于 6.3 s 通过。

## 前端虚拟滚动

- 歌曲表固定行高 36 px、视口 480 px、overscan 6、每页 200 条，按 `count` 计算总高度。
- 10 万条时只渲染约 20 行，滚动触发分页加载。
- **55 fps 未实测**：需要真实 10 万库 + 屏幕录制/性能面板手工验收；当前仅验证构建与逻辑。
